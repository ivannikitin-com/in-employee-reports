# Стандарты Оформления Кода

Для обеспечения чистоты, читаемости и единообразия кодовой базы, проект придерживается официальных стандартов кодирования WordPress.

Соблюдение этих стандартов обязательно для всего нового и изменяемого кода.

## Основные принципы

- **Читаемость**: Код пишется один раз, а читается многократно. Приоритет всегда отдается понятному и ясному коду.
- **Предсказуемость**: Структура кода должна быть предсказуемой, чтобы другие разработчики могли легко ориентироваться в проекте.
- **Согласованность**: Весь код в проекте должен выглядеть так, как будто его написал один человек.

## Руководства по языкам

### PHP

Весь PHP-код должен соответствовать [руководству по PHP от WordPress](https://developer.wordpress.org/coding-standards/wordpress-coding-standards/php/). Ключевые моменты:

- **Отступы**: Используйте табы, а не пробелы.
- **Фигурные скобки**: Открывающая скобка ставится на той же строке, что и начало конструкции, а закрывающая — на новой строке.
- **Именование**: 
	- Имена классов: `Title_Case_With_Underscores`.
	- Имена функций и переменных: `lowercase_with_underscores`.
	- Имена констант: `ALL_CAPS_WITH_UNDERSCORES`.
- **Пробелы**: Соблюдайте правила расстановки пробелов вокруг операторов и после запятых.
- **Yoda Conditions**: Используйте "условия Йоды" для сравнений (`true == $value`).
- **Самодокументируемый код**: Пишите код, который легко понять без комментариев. Используйте комментарии только для объяснения сложной логики ("почему", а не "что").
- **Документация PHPDoc**: Классы и методы должны быть документированы по спецификациям PHPDoc.

### WordPress

Код следует писать без дополнительного усложнения, всегда придерживаясь принципа KISS (Keep It Simple, stupid!). Например, для логирования и отладки НЕ СЛЕДУЕТ ставить дополнительные компоненты PHP, а просто использовать инструкцию:

```php
WP_DEBUG && error_log('Сообщение');
```

Для логирования необходимо выводить сообщения в общий лог `debug.log`, а не формировать свои файлы логов. Сообщения плагина в `debug.log` должны начитаться с префикса `НАЗВАНИЕ_ПЛАГИНА: УРОВЕНЬ_СООБЩЕНИЯ`. Примеры:

- `my-plugin: error: Сообщение об ошибке`
- `my-plugin: info: Информационные сообщения`

Рекомендуемые уровни:

- `error` -- сообщения об ошибках или критических ситуациях, не позволяющих выполнить корректную работу, вывод должен оставаться в коде при подготовке релиза.
- `debug` -- отладочные сообщения, вывод этих сообщений можно удалять из кода после отладки при подготовке релиза.
- `info` -- информационные сообщения, вывод может оставаться в коде при подготовке релиза.

Общий лог WordPress при разработке находится в папке `log/debug.log`.

### JavaScript

Весь JavaScript-код должен соответствовать [руководству по JavaScript от WordPress](https://developer.wordpress.org/coding-standards/wordpress-coding-standards/javascript/).

Предпочтение следует отдавать "ванильному" JavaScript, а не библиотекам типа JQuery. Библиотеки используются только по необходимости.

### HTML и CSS

Для HTML и CSS также применяются [соответствующие стандарты WordPress](https://developer.wordpress.org/coding-standards/wordpress-coding-standards/html-and-css/).
