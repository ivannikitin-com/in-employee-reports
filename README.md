# In-employee-reports: Плагин отчетов сотрудников для WordPress

## Версия 3.0

Версия 3.0 представляет собой полный рефакторинг плагина с фокусом на упрощение архитектуры, повышение производительности и улучшение качества кода.

## Краткое описание

Плагин `in-employee-reports` предназначен для заполнения и проверки отчетов сотрудников "Иван Никитин и партнеры" по выполненным задачам. Плагин предоставляет удобный интерфейс с редактируемой таблицей в стиле Excel/Google Sheets для ввода данных о проектах, времени и ставках.

## Возможности

- **Управление отчетами:** Создание, чтение, обновление и удаление отчетов о выполненных задачах
- **Система ролей:** Две кастомные роли - `employee` (сотрудник) и `head_of_department` (руководитель)
- **Гибкие права доступа:** Использование стандартного механизма WordPress `map_meta_cap` для контроля доступа
- **REST API:** Программный интерфейс для взаимодействия с отчетами из внешних приложений
- **Производительный интерфейс:** Редактирование отчетов на фронтенде с использованием AG Grid Community
- **Экспорт в CSV:** Возможность экспорта отчетов с учетом фильтров
- **Автоматическое сохранение:** Изменения сохраняются автоматически при редактировании
- **Фильтрация данных:** Фильтры по сотруднику, месяцу и году
- **Итоговая статистика:** Автоматический подсчет часов и суммы

## Требования

- **PHP:** 7.4 или выше
- **WordPress:** 5.8 или выше
- **MySQL:** 5.7 или выше

## Установка

1. **Загрузка:**
   - Скачайте последнюю версию плагина с [GitHub Releases](https://github.com/ivannikitin-com/in-employee-reports/releases)
   - Распакуйте архив
   
2. **Загрузка на сервер:**
   - Загрузите распакованную папку `in-employee-reports` в директорию `/wp-content/plugins/` вашего сайта WordPress
   
3. **Активация:**
   - Перейдите в раздел "Плагины" в административной панели WordPress
   - Найдите "Отчеты сотрудников" и нажмите "Активировать"
   - При активации автоматически создаются роли и выполняется миграция (если обновляетесь с версии 2.x)

## Миграция с версии 2.x

При обновлении с версии 2.x на 3.0 автоматически выполняется:

- Создание ролей `employee` и `head_of_department`
- Миграция пользователей с роли `head` на роль `head_of_department`
- Удаление устаревшей роли `head`

**Важно:** Пользователям, использующим REST API, необходимо перейти на встроенные пароли приложений WordPress (см. раздел "Использование").

## Использование

### Настройка ролей пользователей

После активации плагина доступны две роли:

- **Сотрудник (employee):** Может просматривать, создавать, редактировать и удалять только свои отчеты
- **Руководитель (head_of_department):** Может просматривать, редактировать и удалять отчеты всех сотрудников

Назначьте пользователям соответствующие роли в разделе `Пользователи` → `Все пользователи`.

### Создание страницы отчетов

1. Создайте новую страницу или откройте существующую
2. Добавьте шорткод `[in_employee_reports]`
3. Опубликуйте страницу

Страница будет доступна только авторизованным пользователям с ролями `employee`, `head_of_department` или `administrator`.

### Работа с отчетами

На странице отчетов доступны:

- **Фильтры:** Выбор сотрудника, месяца и года
- **Таблица:** Редактируемая таблица с автоматическим сохранением изменений
- **Статистика:** Автоматический подсчет общего количества часов и суммы
- **Экспорт:** Кнопка экспорта данных в формат CSV

### Интеграция с внешними приложениями

Для доступа к REST API плагина используйте **встроенные пароли приложений WordPress**:

1. Перейдите в `Пользователи` → `Профиль`
2. Прокрутите до раздела "Пароли приложений"
3. Введите имя приложения (например, "Excel Integration")
4. Нажмите "Добавить новый пароль приложения"
5. Используйте сгенерированный пароль для Basic Authentication в REST API

**REST API Endpoint:** `https://your-site.com/wp-json/reports/v2/activity/`

## Разработка

### Архитектура

Плагин построен на принципах **KISS (Keep It Simple, Stupid)**, используя стандартные механизмы WordPress для управления ролями и возможностями.

**Основные компоненты:**

- `source/in-employee-reports.php` - Точка входа плагина
- `source/classes/Plugin.php` - Центральный координатор
- `source/classes/Permissions_Manager.php` - Управление ролями и правами доступа через `map_meta_cap`
- `source/classes/Report.php` - Управление Custom Post Type "activity"
- `source/classes/Activity_REST_Controller.php` - REST API для CRUD-операций
- `source/classes/Settings.php` - Управление настройками
- `source/classes/Frontend.php` - Отображение интерфейса на фронтенде
- `source/assets/js/frontend.js` - JavaScript логика с AG Grid

**Технологический стек:**

- Backend: PHP 7.4+, WordPress API
- Frontend: AG Grid Community v31.0, jQuery, Moment.js, Numbro.js
- Тесты: PHPUnit 9.5+
- Стандарты кодирования: WordPress Coding Standards

### Локальная разработка

```bash
# Клонирование репозитория
git clone https://github.com/ivannikitin-com/in-employee-reports.git
cd in-employee-reports

# Установка зависимостей
composer install
npm install

# Сборка фронтенда
npm run build

# Запуск Docker окружения
docker-compose up -d

# Доступ к сайту
# http://127.0.0.1:8080/
```

### Запуск тестов

```bash
# Установка WordPress Test Suite (выполняется один раз)
bash bin/install-wp-tests.sh wordpress_test root '' localhost latest

# Запуск всех тестов
composer test

# Проверка стандартов кодирования
composer lint

# Автоматическое исправление стиля
composer lint-fix
```

Подробнее о тестировании см. в [`docs/TESTS.md`](docs/TESTS.md).
