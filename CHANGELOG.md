# История изменений

Все значимые изменения в этом проекте будут документироваться в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),
и этот проект придерживается [Semantic Versioning](https://semver.org/lang/ru/).

## [3.0.0] 2026-01-24

### Изменено (Breaking Changes)

- **Упрощена система ролей:** Теперь плагин использует только 2 кастомные роли (employee, head_of_department)
- **Роль 'head' удалена:** Существующие пользователи с ролью 'head' автоматически мигрируются на роль 'head_of_department' при активации плагина
- **Удалена кастомная система паролей приложений:** Теперь используются встроенные WordPress Application Passwords (доступны в профиле пользователя)
- **Заменен RoleManager на Permissions_Manager:** Класс переименован и значительно упрощен
- **Заменена таблица Handsontable на AG Grid:** Значительное улучшение производительности и стабильности интерфейса

### Добавлено

- **Использование map_meta_cap:** Вся логика проверки прав доступа делегирована ядру WordPress через хук `map_meta_cap`
- **AG Grid Community (v31.0):** Современная и производительная таблица для редактирования отчетов
- **Экспорт в CSV:** Новая кнопка экспорта отчетов в формат CSV с учетом текущих фильтров
- **Автоматизированные тесты:** Полный набор PHPUnit тестов для всех компонентов плагина
  - Тесты системы ролей и прав (`test-permissions-manager.php`)
  - Тесты REST API (`test-rest-api.php`)
  - Тесты фронтенда (`test-frontend.php`)
- **Стандартное логирование:** Переход на стандартное логирование WordPress в `debug.log`
- **Bootstrap для тестов:** Настройка тестовой среды WordPress для запуска unit-тестов

### Улучшено

- **Архитектура:** Значительно упрощена архитектура плагина, код приведен к принципу KISS
- **Проверка прав:** Все проверки прав используют стандартные функции WordPress (`current_user_can()`)
- **REST API:** Упрощены все методы проверки прав, удалена избыточная логика
- **Производительность таблицы:** AG Grid обеспечивает плавную работу даже с тысячами записей
- **Кодовая база:** Приведена в соответствие с WordPress Coding Standards
- **Безопасность:** Использование стандартных механизмов WordPress для аутентификации
- **Фильтрация в админке:** Улучшена логика фильтрации записей по пользователям

### Удалено

- Кастомная роль 'head' (заменена на head_of_department)
- Кастомная система паролей приложений (генерация ключей через интерфейс плагина)
- Методы аутентификации через `RoleManager::authentificateApplication()`
- Методы генерации ключей `generateKey()`
- Кэширование паролей приложений в транзиентах
- Библиотека Handsontable и все связанные зависимости
- Кастомные логи `activity.log` и `error.log` (заменены на стандартный `debug.log`)

### Миграция с версии 2.x

При активации плагина версии 3.0 автоматически выполняются следующие действия:

1. Создаются роли `employee` и `head_of_department` (если их нет)
2. Все пользователи с ролью `head` автоматически получают роль `head_of_department`
3. Роль `head` удаляется из системы

**Важно:** После обновления пользователям необходимо использовать встроенные пароли приложений WordPress вместо старых ключей из интерфейса плагина.
